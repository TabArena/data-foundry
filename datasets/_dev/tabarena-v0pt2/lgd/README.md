## In brief

**Question.** What share of a defaulted loan's outstanding amount will the bank lose?

**Use case.** When a loan has just defaulted, the bank estimates the share of the outstanding amount it will lose (the task of the book's chapter 10).

**One row.** One defaulted loan of a European bank, "slightly modified and anonymized", from the book Credit Risk Analytics (2,545 loans, 2016; period not stated).

**Predicted.** The loss as a share of the outstanding amount, from 0 to 1; 28.6% of the loans lose nothing and 5.6% lose everything.

**Known at prediction time.** Only the loan-to-value ratio and whether the loan's purpose is renting, as in the book's models.

**What the test data stands for.** Groups of loans that most likely belong to one borrower are held out whole, so each test loan comes from a borrower the model has not seen, as for a new default.

**Our changes to the source.** We drop the transformations of the loss and the flag that marks loans without loss, and group the loans by borrower (runs of rows with one loan-to-value ratio) instead of the record's random split.

> **Use case fit: approximate (a stand-in with a known gap).** The file has no dates, though its row order shows a drift in the losses, so the split cannot place new defaults after old ones. Reading the zero-loss loans as defaults that ended without loss follows the book's code but is not verified.

## Curation notes

We start with lgd.csv from the data page of the book Credit Risk Analytics (Baesens, Roesch and Scheule 2016): 2,545 loans of a European bank, "slightly modified and anonymized" (chapter 1, p. 14).

- Prediction point: a loan has just defaulted, and the bank estimates the share of the amount outstanding it will lose. The loan-to-value ratio and the purpose are known then.
- Target: `lgd` (the source's `lgd_time`), a share from 0 to 1, as regression with RMSE, the book's own task in chapter 10. No log transform: the share has mass points at both bounds. The record asks for binary classification, but the only binary column, `event`, is part of this target.
- We drop `Recovery_rate`, `y_logistic`, `lnrr` and `Y_probit`, transformations of the LGD.
- We drop `event`: it is 0 for exactly the 728 loans at the floor, so it says whether there was a loss (decision table).
- We keep the source's target bounds: an LGD of zero is stored as 0.00001 (28.6% of the loans) and a total loss as 0.99999 (5.6%).
- We rename `LTV` to `loan_to_value` (a share, although the data page says "in %") and `purpose1` to `purpose_renting`.
- Grouped by borrower block (`borrower_block`): a run of consecutive rows with one loan-to-value ratio, which occurs in no other run. 70 of the 488 multi-loan runs mix both purposes, so a run holds different loans, most likely of one borrower, and their LGDs are alike (correlation 0.42 within runs net of LTV and file order, 0.02 between neighbouring runs). A borrower's loans default together, so the losses of the other loans are not known at a new default; each run stays on one side, against the record's "Random (IID)" (decision table).
- Duplicates: the 120 rows that repeat an earlier row of their run and the 397 rows that differ from another loan only in the LGD are loans of one borrower; we keep them, and the grouped split keeps each run on one side.
- Anomaly: the file's row order carries the outcome without a documented meaning (the median LTV and the mean LGD rise along the file); with no dates in the file, the split cannot be temporal.
- Note: we read `event` = 0 as a cure (a default that ended without loss), as the book's Tobit and censored beta code do; its Heckman code treats it as "not selected", and chapter 10 was not read. If these loans never defaulted, the 728 rows do not belong in an LGD target.
- Note: the artefacts for which the book's HMEQ data was retired (homeq_default_prediction) are absent: no run is a jittered copy, and the number format of the LTV does not predict the LGD.
- Note: two features only, as in the book's models. The raw loan-to-value ratio as a monotone fit (skill 0.188) beats a spline on both columns (0.208) on 0 of the 30 shipped splits, so the task is not `Trivial` (task-probe rule 4).

## Group structure

One group is a run of consecutive rows of the source file with the same loan-to-value ratio: 1,958 runs,
488 of them with 2-7 loans. The loans of a run share one loan-to-value ratio. They are most likely one
borrower's loans: 70 of the multi-loan runs mix both loan purposes, and their LGDs correlate (0.42 after
LTV and the file-order trend are removed, 0.02 between neighbouring runs).
The key equals the LTV value, since no value occurs outside its run. The grouping rests on the consecutive
blocks of the file's order, not on a hash of the features.
The book defines LGD by the "default of an obligor" (chapter 1, p. 10), so a borrower's loans default
together. When the model estimates the LGD of a new default, the losses of the borrower's other loans
are therefore not known. Each loan is one prediction from its own row.

## Decisions

### 1. Grouped by borrower block, not IID

The file lists loans with the same loan-to-value ratio as one run of consecutive rows, and many runs mix both loan purposes: a run is most likely several loans of one borrower. Their losses are alike (overall SD of the LGD 0.329) and are not known when a new default is scored, so a run stays on one side of the split.

| loans in the run | runs | rows | runs_with_mixed_purpose | runs_with_loss_and_no_loss | mean_sd_of_lgd_in_run |
|---|---|---|---|---|---|
| 1 | 1470 | 1470 | 0 | 0 | 0 |
| 2 | 415 | 830 | 45 | 70 | 0.104 |
| 3 | 52 | 156 | 13 | 13 | 0.153 |
| 4-7 | 21 | 89 | 12 | 6 | 0.215 |

### 2. `event` is dropped: it says whether the LGD is above the floor

`event` is 0 exactly for the loans whose LGD is stored as 0.00001 (no loss), so it is part of the target, not a feature. The four other dropped columns are transformations of the LGD.
