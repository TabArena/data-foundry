## Comments

⚠️ **AI-FILLED — UNVERIFIED**: triaged by an AI (2026-08-12), no human has verified it. Check the verdict and the fields before relying on them.

**Screening (AI, 2026-10-22):** `No` (`AHDS (Artifical/Handmade/Deterministic/Simulated)`, SEL-16): a testbed capture whose benign side is generated from abstract user profiles, the method and the call of its sibling `intrusion_detection` (CSE-CIC-IDS2018, Lennart `No`).
- Source: Canadian Institute for Cybersecurity, UNB (ids-2017 page), Sharafaldin, Habibi Lashkari & Ghorbani, ICISSP 2018; capture Monday 3 July to Friday 7 July 2017; page: "we built the abstract behaviour of 25 users based on the HTTP, HTTPS, FTP, SSH, and email protocols" with the B-Profile system "to profile the abstract behavior of human interactions"; a testbed of a user profiling agent and 12 victim machines against an attack network; labels by "the time stamp, source, and destination IPs". Versions: CICFlowMeter CSVs (with the tool's documented defects), the BCCC NTLFlowLyzer re-extraction (2025, a profiling system, "not a detection system"), and the corrected labels of Engelen et al. (WTMC 2021).
- Use case: a network operator flags malicious flows; the use case is real, but the benign traffic it would be scored against is scripted (SEL-16, PROV-3), as decided for the 2018 capture.
- Siblings and duplicates: `intrusion_detection` (Lennart `No`: AHDS, profiling not detection), `unsw_nb15` (AI `No`, AHDS, traffic generator), `kddcup99` (`No`); `ctu_13` (AI `TBD -> Yes`, priority 4) is the counter-case with real captured background traffic. External collections: many IDS benchmarks; not in our collections.
- Metric: the paper reports per-classifier precision, recall and F1 (several, MET-5), so none deliberate.
- `Data Quality Issue` should go: the label and flow errors are documented and a corrected release exists (Engelen et al.), so the damage is repairable (PROV-13); the verdict rests on SEL-16.
- Reject check (AI, 2026-10-22): stands. SEL-16 by treat-alike: the CIC page (https://www.unb.ca/cic/datasets/ids-2017.html) says 'we built the abstract behaviour of 25 users' with the B-Profile system for the benign traffic, the same testbed method as CSE-CIC-IDS2018, which Lennart rejected with the AHDS marker (intrusion_detection, checked_by Lennart, CC 2026-08-12). The corrected WTMC 2021 labels keep the same scripted benign traffic. Agree to drop Data Quality Issue (repairable).

The 2017 sibling capture of [[intrusion_detection]] (CSE-CIC-IDS2018), generated by the same CIC profile-based method, so the same criterion 4B call applies: the benign side is traffic generated from abstract user profiles in a testbed, not observed traffic. Recorded because the family was otherwise only half covered.

Three versions exist and they disagree. The original CIC CSVs come from CICFlowMeter, whose own authors list 16 defects they later fixed — incorrect flow creation, empty flow lists for attack pcaps, PSH-flag and Down/Up-ratio bugs, ICMP mishandling, negative IAT values (Shafi et al., Computers & Security 148:104160, 2025, Sec. 4.1.1, p. 8). The BCCC re-release re-extracts ~300 features from the raw pcaps with NTLFlowLyzer, but that paper builds a profiling system, "not a detection system" (Sec. 6.1, p. 12), so it ships no task; its Table 2 also shows how thin the attack classes are (SQL injection 21 -> 24 flows, Heartbleed 11 -> 12). The independent audit (Engelen et al., WTMC 2021; Liu et al., CNS 2022) publishes separately corrected labels.
