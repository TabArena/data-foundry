## Comments

Anomaly detection task, could be framed as classification, unsure

Preprocessing rel: https://www.kaggle.com/code/horikitasaku/pr-auc-0-9054-catboost-baseline

Task looks very cool!

**Assessment (AI, 2026-10-07):** The anomalies are generated, not recorded. The authors' chapter (von Birgelen & Niggemann 2018, doi 10.1007/978-3-662-57805-6_3, Sec. 4.2, p. 49): the evaluation data "was generated by modifying the training cycles ... increasing or decreasing one or multiple signals ..., shortening of cycles and inserting constant sequences. This artificially generated anomalies are labelled". The Kaggle files confirm it: 99.2-99.4% of the label-0 lines of each anomalous file occur verbatim (same timestamps, all 18 signals) in its normal file, and the label is the edit mask shifted by one row. Suggest `No` + `AHDS`; per-row labels on a sensor stream also fit `Time-series (Classification)`. Not added. Licence CC BY-NC-SA 4.0.

**Open issues (AI, 2026-10-07):** not added; recommended `No` (`AHDS`). The anomalies were injected by software into
normal recordings.

1. **Generated anomalies: set the record to `No` + `AHDS`?** Evidence: the chapter quote and the file comparison in
   the assessment above. Implemented now: nothing, no folder. Alternative, if a fault-injection task is wanted
   anyway: the anomalous files only (the normal files would add an unedited copy of every cycle, a copy across any
   split), grouped by cycle (217 cycles, labels per row), signals rounded to integers; untuned LightGBM reaches ROC
   AUC 0.829, and the time in the cycle alone (0.671) carries as much as the 18 signals without it (0.661).

2. **Second marker `Time-series (Classification)`?** Even with recorded failures, the task labels single samples of a
   ~18 Hz sensor stream, and the injected anomalies are defined over time. Secondary to issue 1.

3. **The record's "Preprocessing rel" notebook is not a reference.** `horikitasaku/pr-auc-0-9054-catboost-baseline`
   concatenates the normal and anomalous files (each normal cycle next to its edited copy), sorts all rows by the
   within-cycle timestamp and then takes row differences across cycles, splits rows at random (`StratifiedKFold`,
   shuffled) and early-stops on the test fold. Its PR AUC of 0.905 says nothing about the task.

4. **No other task in the files.** The title's energy optimization compares the normal standard and optimized runs
   (two control programs of one transport operation); the data card offers it for "energy based optimization
   processes", which has no target.

**Assessment (AI, 2026-10-20):** priority 1 for the review of the added dataset: gap -, use case -, source +, shape -, risk - (Open issue 1: generated anomalies; run did not add it and recommends No + AHDS). Software-injected anomalies in sensor recordings (217 cycles) give no real task; it should be rejected rather than added.
