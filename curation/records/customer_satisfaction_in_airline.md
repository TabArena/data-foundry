CC (2026-10-01, Lennart): Leak audit, source deep dive (Kaggle metadata, discussions and files via the kaggle CLI 2.2.2):
- **Chain of uploads.** yakhyojon (2023-10, `Invistico_Airline.csv`; the uploader: "This dataset comes from Coursera platform. I took Google Advanced Data Analytics course") <- sjleshrac "Airlines Customer satisfaction" (2020-03, same file; the uploader: "I got this dataset from a business competition hosted by IIT Roorkee in 2020 ... provided by an airline whose name was not disclosed", hypothetical name "Invistico Airlines") <- johndddddd "Passenger Satisfaction" (files dated 2019-10, threads from 2018; "US Airline passenger satisfaction survey"). teejmahal20 (2020-02) is the cleaned train/test split of johndddddd's other file. The "Source of the dataset?" threads on johndddddd (2018, 25 votes) and teejmahal20 (2020, 31 votes) were never answered by either uploader.
- **The shipped file is a manipulated copy, made before it reached the competition.** johndddddd uploaded two files with the same 129,880 ids: `satisfaction_2015.xlsx` and `satisfaction.xlsx`. `Invistico_Airline.csv` is `satisfaction.xlsx` without `id` and `Gender` (all 129,880 feature rows identical; label renamed). Against `satisfaction_2015.xlsx` the same passengers (identical gender, customer type, age, travel type, class and both delays) have: the 14 rating columns in the same positions under a different header list, so 8 of them carry the wrong name (e.g. "Seat comfort" holds the wifi rating, "Online support" the seat comfort rating); about 9% of rating values changed; flight distance replaced (0.8% equal, ratio 0.34-60x); and 14,659 labels flipped from "neutral or dissatisfied" to "satisfied", none the other way.
- **The flips follow a rule on a dropped column.** Every flipped row is Female, Personal Travel, inflight wifi rating <= 3 and arrival delay <= 130 min (39 with a missing delay); about 95% of the rows meeting that rule were flipped. Gender is then removed from the shipped file, so 11% of the shipped labels come from a rule on a feature the model never sees.
- **The base file has no source and weak signs of generation.** Delayed passengers almost never share a flight (same distance and both delays: 3.0% of rows vs 2.5% with distance shuffled), 21.8% of children aged <= 12 are on business travel, and the age count jumps from 1,110 at 19 to 1,878 at 20. None of this is conclusive alone.
Proposed verdict: No (Retired), Data Quality Issue + Duplicate + Missing source information. Replacing it with the base file (record `us_airline_passenger_satisfaction`) is not recommended: same missing source.

CC (2026-10-01, Lennart): Leak audit, generation test on the base file (`satisfaction_2015.xlsx`, which the shipped file is derived from):
- **The survey ratings are generated by copying columns within customer segments.** Among satisfied loyal business travellers in Business class (39,191 rows), the wifi rating equals the gate-location rating in 95.2% of rows; apart from wifi = 0 there is not one off-diagonal cell, and each value 1-5 holds 7,324-7,589 rows (a uniform rating among "satisfied" passengers). Other segments copy other pairs: departure/arrival time convenience = gate location for loyal business travellers (91-94%), and food and drink = inflight entertainment = cleanliness (96-98%) and ease of online booking = online boarding (93-95%) for disloyal business travellers; personal travellers show none of this. 27 segment-pairs agree on more than 90% of rows. In a real airline survey (rustam32 on Kaggle, built from the Brazilian Ministry of Transport passenger surveys) no pair of ratings agrees more than 68% of the time, even near-synonyms (restroom cleanliness vs restroom maintenance 67%).
- The flight columns are likely taken from real US flight records: distances spike on actual routes (337 mi, LAX-SFO: 841 rows vs 0-170 at +-1-2 mi; 2,475 mi, JFK-LAX: 470 vs about 10) and delays are clipped at 0 like BTS DepDelayMinutes. Passengers do not cluster into flights, so these flight attributes were attached per row rather than surveyed per flight.
Conclusion: the passenger ratings, and with them the label, are synthetic; only the flight columns look real. Together with the rule-based relabelling and misnamed columns of the shipped variant, this supports retiring it (No (Retired), AHDS + Data Quality Issue + Duplicate + Missing source information).

CC (2026-10-01, Lennart): **Retired (No (Retired); AHDS, Data Quality Issue, Duplicate, Missing source information).** Summary of the findings above:
1. **Generated passenger ratings (main reason).** In the base file (johndddddd `satisfaction_2015.xlsx`), rating columns are copied from one another within customer segments: wifi = gate location in 95.2% of the 39,191 satisfied loyal business travellers in Business class, with a uniform 1-5 spread, and 27 segment-pairs of unrelated items agree on more than 90% of rows. In a real airline survey (Brazilian Ministry of Transport) no pair exceeds 68%. The label depends on these ratings, so it is synthetic as well.
2. **The shipped file is a manipulated copy of that base.** Same 129,880 passengers; 8 of 14 rating columns under the wrong name, about 9% of rating values changed, flight distance replaced, and 14,659 labels flipped to "satisfied" by a rule (Female, Personal Travel, wifi <= 3, arrival delay <= 130 min) on Gender, which the shipped file drops.
3. **No traceable source.** Chain yakhyojon (Coursera course) <- sjleshrac "Invistico" (IIT Roorkee competition 2020) <- johndddddd (2018-19); the source threads (25 and 31 votes) were never answered.
4. Only the flight columns look real (distances spike on actual US routes; delays clipped at 0 like BTS), but passengers do not cluster into flights, so they were attached per row.
